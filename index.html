Backup & Restore — ke PC

Wajib, lapis ke-2 selain Firebase
Backup ke PC itu PERLU, walau udah Full Firebase
Firebase itu lapis 1 (biar semua HP sinkron). Backup ke PC itu lapis 2 (kalau Firebase kehapus / akun ke-lock / rules salah / mau audit). File-nya disimpan di PC > Folder Texlab > Backup, plus copy ke Google Drive biar dobel aman. File JSON = bisa di-restore balik 100%. File CSV = buat bos, cuma buat dibaca, nggak bisa di-restore.
Belum pernah backup.

Nama file otomatis ada tanggalnya, contoh: Texlab_Backup_2026-11-26.json. Simpan di PC + copy ke Google Drive. Usahakan backup tiap Jumat / tiap ada laporan penting.

Hati-hati: Restore akan menimpa semua data di portal + Firebase dengan isi file backup. Backup dulu yang sekarang sebelum restore, biar nggak ilang kalau salah pilih file.

Reset menghapus data coba-coba kalau mau mulai ulang. Export dulu sebelum reset.

Cek Keamanan

Admin onlyAudit 26 Nov 2026 — Fix Allowlist, BUKAN Verifikasi Email
Kenapa verifikasi email DIBATALKAN?
Karena login-mu pake @texlab.com yang bukan email beneran. Firebase ngirim link verifikasi ke inbox fahim@texlab.com. Kalau inbox itu nggak ada (nggak ada Google Workspace / cPanel / mailbox Texlab), email-nya nggak akan pernah nyampe, mental / bounce. Jadi kalau tak wajibin verifikasi, sampean sendiri nggak bisa login. Makanya tak ganti cara.
Rules sekarang pake ALLOWLIST: cuma azis@texlab.com, fahim@texlab.com, riski@texlab.com yang boleh baca/tulis. Orang luar bikin akun hacker@texlab.com bakal DITOLAK Firestore, karena namanya nggak ada di daftar.
Login Gate: nggak login nggak bisa liat data. Password tetep wajib, salah password ditolak.
Daftar Akun: cuma admin yang bisa bikin akun di portal. Abis bikin, wajib tambahin email-nya ke Allowlist di Rules, baru bisa baca data.
Riwayat: boleh baca + bikin baru, tapi nggak boleh edit / hapus.
XSS: semua input di-render pake esc().
⚠️ API Key di file HTML: bukan bocor, API Key Firebase web emang boleh keliatan. Yang ngamanin itu Rules Allowlist, bukan nyembunyiin key. Tapi jangan upload file ini ke GitHub publik.
⚠️ Kalau @texlab.com-mu ternyata email beneran: misal sampean punya mailbox di Google Workspace / hosting buat fahim@texlab.com dan bisa buka inbox-nya, bilang aja, tak balikin ke mode verifikasi email. Tapi kalau inbox-nya nggak ada, jangan pake verifikasi.
Wajib lakuin di Console (1x aja):
1. Copy Rules baru di atas (yang ada allowlist) → Firestore → Rules → Publish. Ini yang paling penting, karena Rules lama masih ngebolehin semua @texlab.com.
2. Authentication → Users → pastikan cuma ada 3 akun itu. Kalau ada akun aneh yang sampean nggak kenal, hapus.
3. Kalau mau nambah orang baru, misal andi@texlab.com: bikin akunnya di Authentication → Add user, terus tambahin 'andi@texlab.com' ke daftar di Rules, Publish lagi.

Panduan Cara Pakai Portal

Buat yang baru pertama kali pegang portal ini. Urutannya dari awal sampai akhir, dari login sampai file Excel / PDF ke kirim ke buyer. Kalau udah ngerti, nggak perlu buka ini lagi. Kalau ada anak baru (Fahim, Riski, dll), suruh baca ini dulu 5 menit.

Login → Dashboard cek yang telat → Input Report (SGR baru) → Buka Form LL Bean → Isi + Pilih PASS / FAIL → Simpan Hasil ke Dashboard → Export Excel / PDF → Kirim ke buyer / pabrik → Cek Dashboard + Lab Analysis udah ke-update.

Alur 1 Report, dari awal sampai selesai

1. Login→2. Input Report→3. Isi Form LL Bean→4. PASS / FAIL→5. Simpan ke Dashboard→6. Export Excel / PDF→7. Kirim

Intinya: Test Reports itu database-nya. Form Excel / PDF itu alat bikin file-nya. Dashboard + Lab Analysis itu baca dari Test Reports, bukan dari file Excel-nya. Makanya harus Simpan Hasil ke Dashboard biar nyambung.

1

Login dulu, pakai email @texlab.com

Portal nggak bisa dibuka tanpa login. Pakai email kantor, misal azis@texlab.com.

Klik untuk lihat langkahnya
  1. Buka portal, muncul halaman Login.
  2. Isi Email + Password yang udah didaftarin admin.
  3. Kalau lupa password, minta admin reset, jangan bikin akun baru sendiri.
  4. Kalau udah masuk, nama sampean muncul di pojok kanan atas.

Yang sering salah: login pakai email gmail biasa. Portal ini cuma nerima @texlab.com.

2

Cek Dashboard dulu, ada yang telat nggak?

Sebelum kerja, liat Dashboard. Yang telat / hari ini / besok langsung keliatan.

Klik untuk lihat langkahnya
  1. Di Dashboard, liat Quality Assurance Overview — diagram Pass / Fail.
  2. Liat Notifikasi (lonceng) di atas — ada info Telat, Hari Ini, Besok, Pending, Fail.
  3. Kalau ada yang Telat, kerjain itu dulu.
  4. Filter Applicant di atas kalau mau liat 1 pabrik aja, misal Ungaran / Pringapus / Congol.
3

Input Report baru — 1 SGR = 1 baris

Pabrik kirim sample → lab bikin SGR baru. Jangan numpuk 1 baris buat banyak SGR.

Klik untuk lihat langkahnya
  1. Klik + Input Report di Dashboard / Test Reports.
  2. Isi Report No. misal SGR-1211263155 — harus sama persis kayak di form LL Bean nanti.
  3. Pilih Buyer (LL Bean / dll), Applicant (pabrik pengirim), Style/Code, Test Type.
  4. Isi Deadline buyer-nya. Beda buyer beda deadline, jangan disamain.
  5. Status awal: Masuk kalau baru dateng, Proses kalau lagi dites.
  6. Klik Simpan. Report langsung muncul di Test Reports + Dashboard.

Penting: 1 buyer bisa punya BANYAK report. Misal LL Bean ada 20 report, ya input 20 baris, bukan 1 baris digabung.

4

Buka Form LL Bean — ini alat bikin Excel / PDF

Form ini cuma buat LL Bean. Isinya buat dibikin file, bukan database.

Klik untuk lihat langkahnya
  1. Di Test Reports, cari SGR-nya, klik Buka Form / View Test Report.
  2. Form LL Bean kebuka. Cek Report No. sama Nama Klien udah keisi bener.
  3. Isi semua tabel test-nya, foto sample, dll kayak biasa.
  4. Jangan ganti Report No. di form — harus sama kayak di Test Reports, kalau beda nanti nggak nyambung.
5

Pilih Overall Rating PASS / FAIL — ini kuncinya

Rating di form inilah yang nanti jadi Pass / Fail di Dashboard.

Klik untuk lihat langkahnya
  1. Di form, cari Overall Rating di atas.
  2. Pilih PASS kalau semua lolos, FAIL kalau ada yang gagal.
  3. Kalau masih / atau kosong, Dashboard nggak bakal ke-update. Harus PASS / FAIL.
  4. Kalau ragu, cek lagi tabel test-nya — kalau ada 1 FAIL, Overall-nya FAIL.
6

Klik Simpan Hasil ke Dashboard — biar nggak edit 2x

Ini tombol hijau di bawah form. Sekali klik, Dashboard + Lab Analysis langsung ke-update.

Klik untuk lihat langkahnya
  1. Setelah Rating PASS / FAIL dipilih, klik tombol hijau Simpan Hasil ke Dashboard.
  2. Tunggu tulisan Tersimpan ke Dashboard: SGR-... → Selesai Pass / Fail.
  3. Balik ke Dashboard, diagram Pass / Fail harusnya udah nambah 1.
  4. Kalau sampean langsung klik Export ke Excel / PDF, itu juga otomatis nyambung, jadi nggak perlu klik tombol hijau lagi.

Jangan ubah status manual lagi di Edit Report kalau udah klik tombol hijau — nanti double, history-nya jadi 2x.

7

Export Excel / PDF, terus kirim ke buyer / pabrik

File-nya yang dikirim. Dashboard-nya yang buat pantauan internal.

Klik untuk lihat langkahnya
  1. Klik Export ke Excel buat file .xlsx, atau Export ke PDF buat file .pdf.
  2. Nama file-nya otomatis: ..._Report_SGR-..._LL_Bean.xlsx — jangan diganti manual biar gampang dicari.
  3. Cek file-nya sekali, terus kirim ke buyer / pabrik kayak biasa (email / WA).
  4. Kalau ada revisi, ubah form-nya, pilih Rating lagi, klik Simpan Hasil lagi + Export lagi.
8

Cek Lab Analysis + Test Reports per Buyer

Buat liat performa per buyer, misal LL Bean bulan ini Pass berapa %.

Klik untuk lihat langkahnya
  1. Test Reports → All Buyers → klik LL Bean → keliatan semua report-nya LL Bean doang, misal 20 biji.
  2. Lab Analysis → Breakdown by Buyer → liat LL Bean: Total, Pass Rate, Fail terbanyak di test apa.
  3. Buyer Directory → klik LL Bean → liat profil buyer-nya (deadline, standar, kontak).
  4. Riwayat → liat siapa yang ngubah apa, kapan.

Tanya jawab cepat — yang paling sering ditanyain

Kenapa Dashboard nggak berubah padahal udah Export Excel?

Karena Rating-nya masih / atau Report No. di form beda sama di Test Reports. Cek 2 itu, pilih PASS / FAIL, klik Simpan Hasil ke Dashboard lagi.

Kenapa muncul “Report belum ada di Test Reports”?

Sampean belum Input Report dulu. Form LL Bean itu bukan bikin data baru, dia cuma nyambung ke data yang udah ada. Input dulu di + Input Report, baru buka form-nya.

1 buyer ada banyak report, gimana liatnya?

Di Test Reports, klik chip buyer-nya (misal LL Bean) atau klik buyer di Buyer Directory → View Test Report. Itu cuma filter, datanya tetep sama, cuma tampilannya difilter per buyer.

Kalau salah pilih PASS padahal FAIL, gimana benerinnya?

Buka form-nya lagi, ganti Rating ke FAIL, klik Simpan Hasil lagi. Status-nya bakal ke-update jadi Fail, history-nya kecatet. Jangan edit manual di Edit Report kalau udah pakai tombol hijau, biar history-nya nggak double.

Backup-nya gimana biar aman?

Di Settings → Data & Storage, klik Backup ke PC tiap minggu. File JSON-nya simpen di PC. Kalau ada apa-apa, klik Restore + pilih file-nya.

Siapa yang bisa ubah Settings / tambah buyer / tambah plant?

Cuma Admin (sampean). Member (Fahim, Riski, dll) cuma bisa input + liat, nggak bisa ubah Settings. Kalau mau nambah applicant baru, minta admin atau klik + Applicant Baru di Input Report.

Cheat sheet 1 menit — tempel di dinding lab

Login → Input Report → Buka Form → Isi → Rating PASS / FAIL → Simpan Hasil → Export → Kirim.
Dashboard = pantauan. Form = alat bikin file. Test Reports = database. Jangan kebalik.
